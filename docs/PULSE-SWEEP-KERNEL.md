# Executed SPC sweep-state kernel

September 18, 2026. Experimental implementation; **not integrated or deployed**.
Review: <http://127.0.0.1:8766/sweep-kernel-review-1086/>.

The previous goal turn was progress: actual game/replay tracing established a
timing discrepancy and the executed legacy divider matrix isolated different
reload/disabled behavior. This turn implements the replacement state logic,
not another pitch adjustment to hide a clock difference.

## Implementation

`tools/build_sweep_kernel.py` builds a relocatable **304-byte SPC700 kernel**.
Each voice has four entry points: sweep-register write, timer-low write,
timer-high write, and half-frame clock. Writes take the byte in A. Routines
return with RET and clobber A/X/flags. The caller must provide the events at
the correct time; it must not infer same-value writes from packet differences.

State allocation (provisional until whole-engine integration is audited):

| State | Pulse 1 | Pulse 2 |
| --- | --- | --- |
| Sweep control | `$41` | `$45` |
| Live period | `$7A/$7B` | `$83/$84` |
| Countdown | `$90` | `$91` |
| Reload flag | `$92` | `$93` |

`$94..$97` are shared scratch, so callers must not interleave two routine calls.
There are no DSP accesses or hardware-timer reads. Timer writes preserve the
other live period byte and do not reset the sweep divider. A sweep-control
write always sets reload, including an unchanged value. Each half-frame
advances the divider even when disabled; a due sweep checks enable, nonzero
shift, minimum period and positive overflow. Negative pulse 1 subtracts one
extra. Reload processing happens after a due update, matching the reference.

The kernel is deliberately **not enabled in `build_native.py`**. The current
packet stream does not carry all required write-event metadata or `$4017`
clock-reset semantics. Wiring it into that stream unchanged would conceal
missing inputs rather than fix the scheduler.

## Actual execution, not two copies of a Python model

Separate diagnostic cores:

- `.deps/snes9x-kernel-1082/` includes `tools/spc_sweep_kernel_probe.inc`.
  It loads the generated bytes and runs actual SPC instructions to a return
  sentinel. It checks that untargeted direct-page bytes remain unchanged.
- `.deps/fceumm-kernel-1082/` includes
  `tools/fceumm_sweep_kernel_probe.inc` at the end of `src/sound.c`.
  Its exported diagnostic API invokes **unchanged** `FrameSoundStuff(0)` and
  `Write_PSG`, with the existing uninitialized-game dummy waveform callbacks.
  It does not duplicate their sweep arithmetic in the test code.

`tools/check_sweep_kernel.py` compares actual returned states. Full proof 1085:

- **8,388,608 cases:** both voices, every 11-bit period, every control byte,
  countdown boundary states 0/1/2/8, and reload clear/set.
- **82,080 stateful events:** all initial countdowns 0–8 and all dividers,
  repeated same-value sweep writes, low/high writes interleaved with sweeps,
  disable/re-enable, and every possible timer-write byte.
- **43,343 recorded events:** execute the real NES trace's half-frame updates
  and relevant pulse writes in order. Every resulting period, control,
  countdown and reload flag matches the recorded observation. Startup events
  are included; volume writes that cannot change sweep state are skipped.
- Zero differences or unexpected direct-page changes.
- Five executed mutants rejected: freeze disabled countdown, omit reload,
  lose pulse-1 borrow, accept overflow, and write the other voice's control.
- Matrix half-frame cost **31–244 SPC instruction clocks**. This is not a
  measurement of clock-generation accuracy or end-to-end audio latency.

The independent NES half-frame helper advances both NES voices. Differential
single-voice scenarios only compare their selected voice; their partner is
not used as an oracle. The recorded-trace replay instead invokes each SPC
voice once per its actual recorded half-frame event and compares directly
with that trace, avoiding double-clocking a shared reference half-frame.

Source hashes are captured before the matrix and rechecked afterward. The
source-matched, neutral NES observer prerequisite is also verified. Cores and
generated kernel bytes are bound in the report. Earlier quick report 1083 and
full report 1084 are superseded by the strengthened final proof 1085.

## Reproduction

```sh
python3 -m tools.check_sweep_kernel \
  --spc .deps/snes9x-kernel-1082/libretro/rcr_sweep_kernel_libretro.so \
  --nes .deps/fceumm-kernel-1082/rcr_sweep_kernel_libretro.so \
  --trace build/sweep-timing-nes-1074-sweep.csv --out build/FRESH-kernel-proof
python3 -m tools.build_sweep_kernel_review \
  --proof build/FRESH-kernel-proof/report.json --out build/FRESH-kernel-review
python3 -m unittest discover -s tests -q
```

The optional `--quick` matrix is diagnostic only and is rejected by the review
builder as a substitute for complete execution. **783 unit tests pass**.

## Remaining integration

1. Reserve and validate event metadata across generic APU writes, direct APU
   writes, fused sound commits, packet clear, and the actual receiver. Packet
   `$54` is already the fast-reset pending KON mask: any reuse must extract
   metadata and restore zero before entering that handler. `$56` bit 5 is not
   spare. Preserve low/high timer-write distinction and same-value controls.
2. Drive both voices from a continuous half-frame clock, independent of sweep
   enable and timer reload. Handle `$4017` reset/mode semantics. Do not derive
   sweep time from game-loop speed or use the mismatched legacy per-voice rate.
3. Publish live periods to the DSP with correct mute behavior, without
   disturbing envelope/retrigger/noise/triangle paths.
4. Execute integrated protocol/clock/DSP tests, rerun the full gameplay,
   scrolling and speed comparisons, and qualify physical raw audio before
   promotion. Existing rare combat gaps remain unproven, not fixed by this
   component test.

No new ROM build, Rival input/reset, or OBS configuration change this turn.
The full speed/scrolling/audio goal remains active.
